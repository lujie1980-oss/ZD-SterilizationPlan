### C6-04 非法文件整批不写入，确认按钮禁用

**结论：通过（带风险）。**

错误码对照（提纲 §四 / 设计 §7）与本轮测试：

| 错误码 | 有测？ | 落点 |
|--------|--------|------|
| `MD_PARSE_FAIL` | **有** | 损坏 xlsx / 非 zip 头；空文件 |
| `MD_HEADER_MISMATCH` | **有** | 缺必要列 `foo,bar` |
| `MD_REQUIRED` | **有** | 柜三标识全空；UI 预览文案含 `MD_REQUIRED`，`#btnMasterConfirmImport` disabled |
| `MD_TYPE` | **有** | 柜 `status=维修`；混合批第二行非法枚举 |
| `MD_DUP_KEY` | **有** | 文件内两行相同柜主键 |
| `MD_FK_CABINET` | **有** | 托盘 `柜不存在`；工艺 `柜幽灵` |
| `MD_DUP_LEVEL` | **有** | 同柜两托盘 `level=3` |
| `MD_ENTITY_FORBIDDEN` | **有** | 客户规则 validate/apply/template |

UI：硬错误时确认按钮禁用；预览表展示行号/字段/错误码/原因。`confirmMasterImport` 在 `!report.ok` 时直接 `return false`。

**风险（非阻断，建议 MateBook 补点）：**

1. **domain `applyMasterUpsert` 不检查 `report.ok`。** 非法枚举会被静默落到默认/`existing`（例如 `status=坏了` → `可用`）。混合批若绕过 UI 直接 `apply`，合法行会写入。产品路径被 store 门闩挡住；C6-04 那条「混合批」单测实际是对 **过滤后的合法行** 调用 `apply`，并未断言「对混合行调用 apply 必须抛错」。
2. UI 只点验了 `MD_REQUIRED`；其余码主要在 domain。
3. 与**已有库内托盘**层号冲突的 `MD_DUP_LEVEL` 在代码 merge 段存在，单测用的是文件内两行冲突。

### C6-05 只动主数据，不改 plan 交易

**结论：通过（带风险）。**

| 核对点 | 结果 |
|--------|------|
| 独立存储 key | `STORAGE_KEY_MASTER = 'zhende_sterilization_master_v1'` vs `STORAGE_KEY = 'zhende_sterilization_plan_v2'` |
| 确认导入写哪 | 仅 `saveMaster`；`confirmMasterImport` **不**调用 `persist()` |
| 交易切片 | UI 单测：导入报废柜 `cab-66` 后 `plan_v2` 的 `contents/furnaces`、`tasks`、`config`、`virtualLines` JSON 与导入前一致 |
| StockLine | 导入路径不碰 `pool` / `virtualLines` |
| Content / Task | 导入路径不改 `this.furnaces` / `this.tasks` |
| 停用/报废不级联删组柜 | upsert 只替换 `masterCabinets`；无按柜删 `furnaces` 逻辑；`usableCabinets` 仅过滤展示/选柜 |
| Vue → store | 组柜/甘特/事实条从 seed 常量改为 `plan.master*`（读主数据，不是写交易） |

**风险（非阻断）：**

- `loadPlan(master)` / `migrateContents` 在 **hydrate** 时用当前柜/托盘主数据 `normalizeCabinetContent`。导入当下不写 `plan_v2`；若之后刷新再做任意会 `persist()` 的操作，可能把按新托盘主数据重算的 Content 派生字段写回计划 key。与「导入瞬间零写交易」不冲突，但跨会话有间接写回窗口。MateBook 可在导入后立刻看 DevTools：只应多出 `zhende_sterilization_master_v1`，`plan_v2` 哈希不变。
