## 3. 铁律核对（硬失败条件）

详细设计 §1 / 提纲 §3：首版不手工并箱；N 箱 → N 单元；无 PlanUnit 不可装；`unassigned ↔ placement=null`；组柜不建 CabinetTask。

| 铁律 | 结论 | 量化 / 源码证据 |
|------|------|-----------------|
| F1 `ruleCode=oneBoxOneUnit`，N 箱 → N 单元 | **成立** | `createOneBoxOneUnit` 按 `line.boxes` 生成；`applyPlanUnitCreation` 写 `sourceBoxCount=createdCount=N`。C7-01 单测 boxes=3 → 3 单元 `boxSeq=[1,2,3]`。jsdom P016 同。未见并箱 UI/API |
| F2 无 PlanUnit 不可装 | **成立** | `manualPackCabinet({ planUnitIds: [] })` 返回「无计划单元不可装」。`autoPackCabinet` 在传入空 `planUnits` 时直接失败。组柜文案「无计划单元不可装 · 请先确认分拆」 |
| F3 `unassigned ↔ placement=null`；一单元最多一槽 | **成立** | `assertPlanUnitInvariant`；`onTrayRowForUnit` 固定 `boxes: 1`。重复挂载 → `ON_TRAY_QTY_OVERFLOW`「计划单元重复装载」 |
| F4 组柜不建 date/shift/Task | **成立** | `draftFromUnits` 字面量 `date: null, shift: null, taskId: null`。探针手动组柜后 Task 数不变。`applyGanttSchedule` / `syncFurnacePlan` 才写 Task。进入 `/gantt` 会 silent 同步（变更-1 既有，见 §6） |
| F5 已放置阻断重跑 | **成立** | `rerunPlanUnitCreation` / `applyPlanUnitCreation` 遇 placed → `PU_RECREATE_BLOCKED`，返回原 `planUnits`/`creations`。jsdom toast 含该码，version 不变 |
| F6 迁移失败保留旧装载 | **成立（领域）** | `migratePlanToPlanUnits` catch 返回原 `contents` + `PU_MIGRATE_FAIL`。`loadPlan` 非稀疏路径写入 `migrateError` 且不 `savePlan`。`hydrate` toast 错误。稀疏+演示种子 wipe 见 §6 |
