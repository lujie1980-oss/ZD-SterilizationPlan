## 3. 闸门与码名对齐（热修 `4c48eca` 要点）

旧名 `TRAY_OVER` / `LOAD_COMPLETE_BLOCK` / `QTY_EXCEEDED` 已删除。当前仓库全文检索仅定稿三码。

`decideCommit` 铁律未改：

- `effectiveGate`：`editSource==='auto'` 一律走 auto 闸
- auto + 任一 `sev==='error'` → `aborted`，`persisted = clone(previous)`
- manual + error → 写入并 `manualViolation`，`needsOverridePrompt`

因此 C1-28/31/40 只要规则层推 **error**，auto 必拒；C1-28/31 单测已直接断言该闸。

## 5. 残余（不挡合入）

1. **未做浏览器点选**。定稿手验（柜9「超托盘」、装填完毕后再自动/手工组柜、校验中心三码）本轮用领域单测 + UI 契约 HTML 代替。
2. **C1-40 无 manual 专测**。定稿只写 auto 拒；若后续要把「手工可落盘+强预警」写成与 C1-28 同级硬条件，需补一条。
3. **auto 组柜对超托盘是「跳过该行」**：空柜自动组柜可能 toast「无可用行」或只装未超托盘行，而不在 `packed.issues` 里带回 `TRAY_OVERFLOW`。落盘闸仍由 `decideCommit` 兜住构造出的超容载荷。
4. **`validateFurnace` 在 `loadComplete` 时始终推 `REPACK_AFTER_LOAD_COMPLETE`**（不必已发生再拼）。装填完毕后校验中心会一直挂该 error；与「再拼才预警」的字面相比偏严，但 auto 禁再拼 / manual 强预警的行为符合定稿。
5. **`changedFurnaceIds` 不侦测 `loadComplete` 翻转**。标装填完毕走 `markLoadComplete` 直写，不经 `decideCommit`；再拼改 `lines` 时闸门仍生效。
